# 0.3.2 問答速度優化

日期：2026-11-23。M2 與 v6 知識庫沿用既有版本；本版調整服務執行與排序分批，並新增精確問題的檢索快取。

## 實測結果

同一台開發電腦、相同 HTTPS 入口、相同兩道問題，每次用新 UUID 發起真正的 M2 推論。先量測原服務，再部署優化並待預載入完成後比較；各組僅兩筆，不是大量負載測試。

| 問題 | 原版本 | 優化後首次查詢 | 命中檢索快取後重問 |
|---|---:|---:|---:|
| 虱目魚寒流前需確認的資料 | 25.423 秒 | 19.201 秒 | 4.969 秒 |
| 虱目魚常見養殖方式 | 27.619 秒 | 20.160 秒 | 5.722 秒 |
| **平均** | **26.521 秒** | **19.681 秒** | **5.346 秒** |

首次查詢平均縮短 **25.8%**；命中檢索快取後，比原版本平均縮短 **79.8%**。快取沒有命中時，仍須完成真正檢索與排序，不能承諾所有問題都在 5 秒內回答。

本次原服務重新量測為約 26.5 秒，和前版驗收的 81 秒／含重啟斷線約 5 分鐘屬不同環境與情境；上表採用本次同題比較，避免把舊觀察當成直接基準。

詳細測量、模型身分、來源摘要雜湊及各階段耗時見 [performance-results.json](performance-results.json)。

## 實際調整

1. **按長度分批排序**：完整保留 40 個候選、FP32 權重、512 token 長度與既有來源檢查；減少每批補齊空白的運算，分數再放回原候選位置。同一批 40 個片段實測由 18.389 秒降至 11.899 秒，前五名一致，最大分數差約 0.0000057；較後方近似同分項目有次序差異。
2. **固定推論工作執行緒**：重用同一個服務工作執行緒，明確設定本機測得合適的 CPU 執行數；不為每次請求重建推論執行環境。CPU 設定在模型運算前完成，參考 [PyTorch 官方說明](https://docs.pytorch.org/docs/stable/generated/torch.set_num_threads.html)。
3. **啟動預載入**：服務啟動後先準備知識庫、排序模型、嵌入模型與 M2。此次約 **68.47 秒**完成準備；此成本仍存在，剛重啟便提問仍可能等待。M2 使用官方空提示載入方式，參考 [Ollama API](https://github.com/ollama/ollama/blob/main/docs/api.md)。
4. **精確檢索快取**：只快取檢索結果，容量 16 題；問題、魚種、結果上限、知識庫版本／雜湊、規則版本與排序模型路徑皆須一致。每次回傳獨立副本，重啟清除；沒有模糊匹配或回答快取。每筆新請求仍由 M2 重新生成，再走既有引用與回答守門。
5. **手機完成回報**：輪詢間隔由 2 秒改為 1 秒，總等待預算仍為 10 分鐘，斷線接續沿用同一識別碼。

## 品質與範圍

六筆比較均核對同一個 M2 digest；兩題優化前後與重問時的檢索內容摘要一致。每次有不同生成嘗試，答案來源為 MODEL_GENERATED，引用逐字檢查通過。這確認本次速度調整仍有實際推論與來源依據，並非完整語義正確率評估。

預設 CPU 設定依這台電腦量測，其他硬體應重新測量。部署需將 `serving_runtime.py` 與 `mobile_gateway.py` 放在既有 API 旁，整合差異見 [server/](../server/README.md)。模型、知識庫、憑證、私密計時紀錄不納入公開 repo。

README 已替換為安裝後 APK 畫面，來源為 Android 15 模擬器；本次沒有連接實體手機，尚不宣稱實體 Android 或 iPhone 驗證通過。
